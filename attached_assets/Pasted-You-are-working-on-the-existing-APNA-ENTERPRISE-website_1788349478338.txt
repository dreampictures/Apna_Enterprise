==================================================

Current route:

/pdf-compressor

1. PDF Compressor
2. Image Compressor

4. Merge/Edit PDF

These tools currently work browser-side and utility files are not uploaded to the server.

Implement the following improvements.

------------------------------------------
1A. AUTO REMOVE FILE AFTER DOWNLOAD
------------------------------------------

When a user completes processing and downloads the generated output file:

- Automatically clear the uploaded file.
- Reset the current tool state.
- Reset the upload area to its initial empty state.
- Clear temporary processing state.
- Allow the user to immediately upload another file.

This should happen after the download action is successfully triggered.

Apply this behavior consistently to relevant PDF and image tools.

Do not affect files before the user has downloaded the output.

------------------------------------------
1B. WARNING BEFORE SWITCHING TOOL
------------------------------------------

Current problem:

When a file is uploaded in one tool and the user clicks another tool/tab, the uploaded file may be removed automatically.

New behavior:

If the current tool contains:

- an uploaded file
- uploaded images
- edited PDF state
- or any unsaved/current work

and the user tries to switch to another tool:

Show a confirmation dialog BEFORE clearing anything.

English version example:

Title:
Leave this tool?

Message:
You have an uploaded file or unfinished work. If you leave this tool, your current file and work will be removed.

Buttons:

Cancel
Leave Tool

Behavior:

Cancel:
- Stay on the current tool.
- Preserve all uploaded files and current state.

Leave Tool:
- Clear current tool files/state.
- Switch to the selected tool.

IMPORTANT:

Do not automatically delete an uploaded file merely because the user clicked another tool.

The warning should appear only when there is actual work that would be lost.

------------------------------------------
1C. ORIGINAL FILE NAME ON DOWNLOAD
------------------------------------------

Current problem:

Processed files are downloaded with renamed or generic file names.

New behavior:

Preserve the original uploaded filename base whenever possible.

Example:

Uploaded:

my-document.pdf

Downloaded:

my-document.pdf

If a suffix is necessary to distinguish the processed file:

my-document-compressed.pdf

Requirements:

- Preserve the original base filename.
- Preserve the appropriate file extension.
- Do not use unnecessary random filenames.
- Apply consistently to all relevant PDF/image tools.

For multiple images converted into one PDF, use a sensible descriptive filename.

Example:

images-to-pdf.pdf

------------------------------------------
1D. PDF COMPRESSOR TARGET SIZE
------------------------------------------

Current problem:

The PDF compression target slider only supports a limited range, approximately down to 500 KB.

New requirement:

Allow target size selection down to:

10 KB

The UI should support:

- Slider control
- Manual numeric input
- Unit selection or clear handling for KB/MB if necessary

The slider and manual value must stay synchronized.

Example:

If the user moves the slider:

Manual value updates.

If the user manually enters a valid target size:

Slider updates accordingly.

Support sensible values such as:

10 KB
20 KB
50 KB
100 KB
500 KB
1 MB
and larger supported values.

IMPORTANT TECHNICAL RULE:

Do not create corrupted PDFs.
